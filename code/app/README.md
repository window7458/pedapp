# SayEye 앱 (서버는 노트북/GPU, 보행자 · 보호자는 폰 브라우저)

시각장애인 보행 보조: **스마트폰 카메라의 실시간 영상**을 서버가 받아 팀 YOLO + 임태규 v12.1 트리거로 판정하고,
위험을 **폰 음성 · 진동**으로 먼저 알린다. 보호자는 별도 화면에서 **푸시 알림 · 위치 지도 · 실시간 영상 · 위험 구간 영상**을 본다.

```
 보행자 폰 (카메라 · 센서 · 음성 · 항상 듣기 · GPS) ──▶ 서버 (FastAPI) ─┬─ ① 팀 10클래스 YOLO (트리거가 직접 추론)
                                                        │              ├─ ② v12.1 트리거 + 폰 센서(기울기 · 회전 · 걸음)
                                                        │              └─ ③ 음성 (Google TTS Zephyr)
 보호자 폰 ◀── 알림 · 사진 · 위험 구간 영상 · 위치 · 실시간 영상 · 푸시 ──┘
```

## 빠른 시작
1. 이 저장소를 받고 `code/app` 폴더에서 `pip install -r requirements.txt` (파이썬 3.10+, GPU면 PyTorch CUDA 버전을 먼저 설치).
2. **Google Drive 의 팀 가중치 `final_10class_best.pt` 를 `code/app/weights/` 에 넣기.** (없으면 서버가 안 켜지고 넣을 곳을 알려 줘요.)
3. 서버 켜기: **`run.bat`** (맥/리눅스 `run.sh`). GPU 서버면 `run_gpu.sh`.
4. 폰 카메라 · 푸시 알림은 **HTTPS 주소**가 필요해요. 다른 터미널에서 `cloudflared tunnel --url http://localhost:8080` → 나온 `https://…trycloudflare.com` 주소를 폰에서 열기.
   - **아이폰은 사파리로** 여세요 (아이폰 크롬은 카메라 불가).
   - 폰에서 **홈 화면에 추가**하면 앱처럼 열려요. 아이폰 푸시 알림은 홈 화면에 추가한 앱에서만 켤 수 있어요(iOS 16.4+).
5. 보호자: 같은 주소 뒤에 `/guardian` + 터미널에 뜬 확인번호. 개발자 화면은 `/dev`.

## 폰 센서 기록 · 접속 키
- 앱을 켜면 GPS · 자이로 · 가속도 · 중력 · 방향 · 나침반을 자동으로 모아 `sessions/`에 Sensor Logger와 같은 형식의 CSV로 저장해요. 지금은 기록만 하고 판단에는 안 써요.
- 아이폰은 자이로 권한을 화면을 누른 순간에만 물을 수 있어요. 걸음 수 · 활동 · 기압계는 웹으로 못 읽어요.
- 공개 주소로 열 때는 `--key` 를 꼭 지정해요 (`https://주소/?k=키`).

## VLM
경고에 VLM 설명을 붙이던 기능과 5초마다 특별 장면을 묻던 기능은 **뺐다**(경고는 트리거 문장만, VLM 때문에 늦어지지 않게).
VLM은 보행자가 **"주변 설명해줘"** 라고 할 때만 SJ 브랜치의 "말로 듣는 풍경" 서버(`/api/text`)로 묘사를 받는 방식으로 붙일 예정.

## 경고 범위 · 녹화
- 보행자에게 말하는 것: **사람 · 탈것(자동차 · 버스 · 오토바이 · 자전거 · 킥보드) · 장애물(기둥 · 볼라드 · 벽 …) · 신호 바뀜**. 무엇을 말할지는 v12.1 트리거 규칙을 그대로 따라요.
- 위험 구간 영상은 **사람 · 탈것 경고(긴급 · 주의)와 보행자 호출**일 때만 저장 (경고 5초 전 ~ 4초 후, 이어지면 최대 30초).
- 화면 색: 평소 파랑 · 주의 노랑 · 위험 빨강.

## 판단: 임태규 v12.1 트리거 (`--trigger nav`, 기본)

taegyu 브랜치 `navigation_trigger/`를 **고치지 않고 그대로** 가져왔어요 (`navigation_trigger/trigger/`). 모델은 같은 팀 `final_10class_best.pt`(해시 같음)를 `weights/`에서 씁니다.
`nav_trigger.py`는 연결만 해요. 이 트리거는 자기 안에서 YOLO 추론(전체 + 0.4 s마다 잘라 보기), 추적, 카메라 움직임, 보행 방향, 신호등 색까지 직접 계산하기 때문에 **앱의 YoloTracker를 따로 돌리지 않고 이 객체가 인식기와 트리거를 함께 맡아요** (같은 모델을 두 번 돌리면 CPU에서 너무 느려요).

- 경고 문장은 트리거가 만든 그대로: `12시 방향, 이동 중인 차량에 유의하세요.` / `신호가 초록불로 바뀌었습니다.`
- 화면 단계: 트리거의 `priority=urgent` → 빨강(위험), 그 밖 접근 경고 → 노랑(주의), 신호 바뀜 → 안내만.
- 같은 대상 재경고 · 같은 종류 쿨다운은 트리거가 이미 해서 앱은 다시 거르지 않아요.
- 입력 크기: CPU 640 · GPU 960 (원본 기본 960). `--imgsz`, 느린 CPU면 `--no-crop`.
- 시간은 서버가 프레임을 받은 실제 시각을 써요. 처리가 느려 프레임 간격이 길어지면 트리거의 연속 관측 조건이 끊겨 경고가 늦거나 안 나올 수 있어요 → 실사용은 GPU 권장.

## 얼굴 가리기 (`face_blur.py`)
- 판단(인식 · 트리거)은 **원본**으로 하고, 그 다음에 얼굴을 가린 사본을 만들어 **밖으로 나가거나 저장되는 영상**에만 써요: 보호자 실시간 영상 · 지금 화면 · 알림 사진 · 위험 구간 녹화 · 장애물 원본 저장 · VLM 입력.
- YuNet 얼굴 검출(OpenCV 내장, `weights/face_yunet.onnx` 230 KB, 긴 변 640) + 이미 나온 사람 박스의 머리 부분. 노트북 CPU 프레임당 약 30–40 ms.
- 끄기: `--no-face-blur` (또는 `FACE_BLUR=0`).

## Cloud Run (상시 주소, 안 쓰면 0원)
저장소 루트의 `Dockerfile` · `.gcloudignore` · `deploy/`. 접속이 없으면 서버가 0대로 꺼지고, 폰이 열면 켜져요(첫 접속 10–20 s).
```powershell
.\deploy\deploy_cpu.ps1 -Project 프로젝트ID -Key 접속키 -Pin 보호자번호   # CPU (서울)
.\deploy\deploy_gpu.ps1 -Project 프로젝트ID -Key 접속키 -Pin 보호자번호   # 필요할 때 쓰는 L4 GPU 서비스 (결제 계정 필요)
```
최대 1대로 고정해요 (보행자 폰과 보호자 화면이 같은 서버 메모리를 봐야 해서). 알림 · 기록 파일은 서버가 꺼지면 사라져요.

## 보행자 화면 / 보호자 화면

| 주소 | 누가 | 내용 |
|---|---|---|
| `/` | 보행자 | 위쪽은 상태를 말해 주는 영역(누르면 다시 듣기), 아래는 시작 · 중지 카드와 다시 듣기 · 보호자 호출 타일 |
| `/guardian` | 보호자 | 오늘 요약 · 위치 지도 · 최근 알림(사진 · 위험 구간 영상) · 실시간 영상 · 푸시 알림. 확인번호 필요 |
| `/dev` | 개발자 | 박스 · 단계 표시가 있는 확인용 화면 |

**보행자**
- **항상 듣기**(기본 켜짐): 버튼 없이 "시작", "그만", "다시 말해줘", "도와줘", "소리 키워", "천천히"를 알아들어요. 지나가는 대화를 명령으로 오해하지 않게 **짧은 말이거나 "세이아이"로 부를 때만** 받아요. 앱이 말하는 동안은 잠시 듣기를 멈춰요. 브라우저 음성 인식이라 안드로이드 크롬이 가장 안정적이고, 아이폰 사파리는 화면이 켜져 있을 때만 되고 가끔 끊길 수 있어요.
- 터치 안내(기본 켜짐): 한 번 누르면 이름을 읽고, 4초 안에 한 번 더 누르면 실행. 스크린리더를 쓰면 끄세요.
- 위치 공유(기본 켜짐): 안내 중에만 5초에 한 번 보호자에게 위치를 보내요.
- **처음 설정은 음성으로**: 화면을 한 번 누르면 빛나는 동그라미가 나이 → 키 → 카메라 위치 → 확인을 묻고, 말로 답하면 저장돼요. 끝나면 정한 값을 한 번 더 말해 줘요. 도우미는 "버튼으로 설정하기".
- **계단**: 정면 가까이 계단이 보이면 "앞에 내려가는 계단이 있어요"(긴급) / "올라가는 계단" (지평선 기준).
- **"511번 탈게"**: 도착 정보(20초마다)로 곧 오면 "타셔야 하는 511번 버스가 곧 와요", 안내 중 카메라에 큰 버스가 잡히면 "타셔야 하는 511번 버스가 앞에 왔어요" 바로. 다른 버스면 "다른 버스예요". "버스 탔어" · "그만 기다려"로 끝. 기다리는 버스가 없을 때 "이 버스 몇 번이야"는 풍경 서버가 번호를 읽어요.
- **"길 건널게"**: 건너는 동안 가슴에 단 폰 방향이 18° 넘게 틀어지면 "왼쪽/오른쪽으로 조금". 길 안내 중 횡단보도에서는 자동.
- **CPU 서버 차단**: 실제 인식기를 GPU 로 못 돌리는 서버는 보행자 연결을 거절해요(앱은 한 번만 알림). 노트북 개발은 `ALLOW_CPU=1`.
- 경고는 효과음 · 진동 · 음성 순서, 급한 경고가 덜 급한 말을 끊어요. 영상 끊김 · 서버 재연결 · 배터리 20% 이하 · 카메라 권한도 음성으로 알려요.

**보호자**
- 알림 단계: 긴급 · 주의 · 안내 · 호출 · 연결 · 배터리. 위험 순간 사진(박스 표시)과 위험 구간 영상, 그때의 위치가 붙어요.
- **푸시 알림**: 설정 → 푸시 알림 켜기. 화면을 닫아도 폰 알림으로 와요 (HTTPS 주소 필요, 아이폰은 홈 화면에 추가한 앱에서).
- **실시간 영상**: 보행자 카메라 영상(인식 박스 포함, 약 7 fps). 보는 동안만 서버가 영상을 만들어요.
- **위치**: 지도(OpenStreetMap)에 보행자 위치와 오차 범위를 보여 줘요.
- 내역은 서버 `alerts/`에 최근 500건. 사진 · 영상에 보행자 주변이 찍히니 공유하지 마세요.

## 외부 API 기능 — 길 안내 · 버스 · 지하철 · 음성

모두 **물어볼 때만 대답**하고 평소엔 조용하다(위험 경고가 묻히지 않게). 장애물 경고(태규 트리거)는 건드리지 않는다.
키는 배포하는 PC의 `~/.sayeye_deploy.txt` 에만 두고 저장소에는 넣지 않는다. `deploy/deploy_all.ps1` 이 읽어서 서버 환경 변수로 넣는다.

| 키 (환경 변수) | 발급처 | 쓰는 기능 |
|---|---|---|
| `TMAP_KEY` | SK open API (TMAP) | 장소 찾기 · 걷는 길 · 가까운 지하철역 찾기 |
| `DATA_GO_KR_KEY` | 공공데이터포털 (일반 인증키 하나, 서비스마다 활용신청) | 버스 도착 |
| `KRIC_KEY` | 철도산업정보센터 레일포털 (오퍼레이션마다 신청, 키는 같음) | 지하철 엘리베이터 · 다음 열차 · 승강장 가는 길 |
| (Cloud Run 서비스 계정) | Google Cloud Text-to-Speech | 앱의 모든 음성 |

### 1. 도보 길 안내 — TMAP (`code/app/nav.py`)
| 기능 | 이렇게 말한다 | 하는 일 |
|---|---|---|
| 장소 찾기 | "인하대역 가자" · "인하대역 4번 출구 가자" · "OO까지 길 안내해줘" | TMAP 장소 찾기(`GET /tmap/pois`). 이름이 똑같은 곳 > 그 이름으로 시작 > 들어 있음 순, 같으면 가까운 곳. `부평역[인천1호선]` 의 `[…]` 는 떼고 비교, `역이름 N번출구` 도 같은 이름으로 침 |
| 걷는 길 | (위와 같이) → "인하대역까지 480미터, 걸어서 약 7분이에요." | TMAP 보행자 길(`POST /tmap/routes/pedestrian`, `searchOption=30` 최단거리 + **계단 제외**) |
| 갈림길 안내 | 갈림길 25 m 앞에서 "왼쪽으로 돈 뒤 보행자도로를 따라 110미터 가세요." | TMAP 안내문을 말하기 좋게 바꿈 (`좌회전 후` → `왼쪽으로 돈 뒤`, `111m 이동` → `110미터 가세요`) |
| 횡단보도 | "횡단보도예요. 신호를 확인하세요. …" | TMAP `turnType` 211~217 |
| **휘는 길** | 휘기 시작하는 곳 25 m 앞에서 "길이 오른쪽으로 (크게) 휘어져요. 길을 따라 가세요." | TMAP 이 안내하지 않는 완만한 커브를 경로 선에서 찾는다. 5 m마다 앞뒤 15 m 방향을 비교해, 같은 쪽으로 계속 꺾이는 구간을 묶고 합계 35° 이상이면 안내(70° 이상은 "크게"). 갈림길 · 횡단보도 30 m 안은 빼고, 커브끼리 40 m 넘게 떨어뜨림. GPS 가 지나쳐 버린 커브는 늦게 말하지 않음 |
| 다시 찾기 | "길에서 벗어나서 다시 찾았어요." | 경로 선에서 40 m 넘게 두 번 연속 벗어나면 |
| 도착 | "인하대역에 도착했어요." | 20 m 안. 보호자에게 도착 알림(위치 없이). 역이면 "엘리베이터 어디야라고 말하세요" |
| 멈추기 | "길 안내 그만" | |
| 예비 | — | TMAP 키가 없거나 실패하면 OpenStreetMap(Nominatim 장소 + OSRM 도보, 키 없음) |

- 폰 GPS 정확도가 50 m보다 나쁜 위치는 버린다. 장애물 경고는 길 안내와 함께 그대로 돈다.
- 실제 경로로 확인: 인하대역 · 인천대공원(곧은 길, 커브 안내 0번) / 월미공원(굽은 월미로에서만 3번).

### 3. 지하철 — 철도산업정보센터 KRIC (`code/app/subway.py`)
| 기능 | 이렇게 말한다 | 대답 예 | KRIC 오퍼레이션 |
|---|---|---|---|
| 역 엘리베이터 | "인하대역 엘리베이터 어디야" · "엘리베이터 어디 있어"(가장 가까운 역) | "인하대역 엘리베이터는 4곳이에요. 밖으로 나가는 건 1번 2번 출구 사이, 6번 7번 출구 사이에 있어요. 승강장으로 가는 건 …" | `convenientInfo/stationElevator` |
| 다음 열차 (시간표 기준) | "인하대역 지하철 언제 와" · "부평역 전철 몇 분 남았어" | "수인분당 송도 쪽은 4분 뒤, 다음 차 11분 뒤. 숭의 쪽은 8분 뒤 … 실제 도착은 조금 다를 수 있어요." | `trainUseInfo/subwayTimetable` |
| 승강장 가는 길 | "인하대역 1번 출구에서 송도 방면 가는 길" | "1, 1번 2번 출입구 지상 1층 엘리베이터 탑승. 2, 지하 1층. 3, 표 받는 곳 통과. … 6, 송도 방면 승강장." | `handicapped/stationMovement` |

- **역 이름 → 코드:** `code/app/kric_stations.csv` (KRIC 역사 코드표, 전국 1,108역 · 운영기관/노선/역 코드. 출처: 공개 저장소 paradomi/tooktar `data/station_codes.csv`, 원본은 레일포털 자료실 "역사코드정보"). 역 이름을 말하지 않으면 TMAP 으로 가장 가까운 지하철역을 찾는다. 노선이 여럿인 역(부평: 1호선 · 인천1호선)은 모두 본다.
- **열차 방향:** 시간표 응답에 방향이 없다. 옆 역 시간표에서 같은 열차 번호가 **더 늦게** 지나가면 그 역 쪽으로 가는 열차로 본다. 바로 옆 역에 안 서고 2~3정거장 뒤에서 잡히는 열차는 "급행"이라고 말한다. 평일 `dayCd=8`, 주말 `9`(공휴일은 따로 구분 안 함). 서버는 UTC 라 한국 시각(+9)으로 계산한다.
- **엘리베이터 말하기:** 밖(지상)으로 나가는 것은 출구 번호로("1,2" → "1번 2번 출구 사이", "1~4" → "1번에서 4번 출구 쪽"), 승강장 쪽은 위치 설명 첫 구간만 짧게.
- **승강장 가는 길:** 출구 · 방향을 안 말하면 고를 수 있는 출발점과 방향을 알려 주고 예시 문장을 말해 준다.
- **요청 횟수:** KRIC 요청("시간표 말고는 분기 · 반기마다 바뀌니 하루 1번 정도만")대로 같은 요청은 메모리와 버킷(`/data/kric_cache/`)에 저장해 다시 쓴다 — 시간표 1일, 엘리베이터 · 이동 경로 7일. 처음 묻는 역은 4~6초, 그다음은 바로.
- **안 쓴 것:** 환승 이동경로(`vulnerableUserInfo/transferMovement`)는 키를 받았지만 확인한 역(부평)에 데이터가 없어 넣지 않았다. 급행 시각표(`subwayTimetableExp`)는 위 방법으로 급행을 알 수 있어 따로 쓰지 않았다. 실시간 도착(서울 열린데이터광장)은 시간표로 대신했다.
- 확인한 역: 인하대 · 부평 · 주안 · 인천시청 · 강남 (코레일 · 인천교통공사 · 서울교통공사).

### 4. 음성 — Google Cloud Text-to-Speech
앱이 말하는 모든 문장을 `ko-KR-Chirp3-HD-Zephyr` 로 읽는다. 속도 1.1, 경고 206문장 미리 합성(`app_tts.py`).

### 5. 서버 API (앱이 부르는 주소)
| 주소 | 하는 일 |
|---|---|
| `GET /api/nav?q=&lat=&lon=` | 장소 찾기 + 걷는 길 (안내 단계 · 경로 선 · 첫 안내 문장) |
| `GET /api/nav/route?lat=&lon=&dlat=&dlon=&name=` | 길 다시 찾기 |
| `GET /api/bus?lat=&lon=&route=` | 가까운 정류장 버스 도착 |
| `GET /api/elevator?q=` 또는 `?lat=&lon=` | 역 엘리베이터 |
| `GET /api/train?q=` 또는 `?lat=&lon=` | 시간표 기준 다음 열차 |
| `GET /api/platform?q=&exit=&dir=` | 출입구 → 승강장 가는 길 |
| `GET /api/tts?t=` | Zephyr 음성 MP3 |

키가 없으면 503, 장소 · 역을 못 찾으면 404, 바깥 API 가 실패하면 502 → 앱은 "지금은 … 받을 수 없어요"라고 말한다.
시험: `tests/nav_curve_test.py`(휘는 길) · `tests/elevator_test.py`(지하철 문장 + `KRIC_KEY` 가 있으면 실제 호출).
